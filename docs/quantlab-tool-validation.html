TOOL CALLING · VALIDATION · DATA QUALITY

QuantLab Agent
工具调用、结果校验与数据异常检测

核心思想：LLM 可以提出“要做什么”，但不能直接执行代码或自行宣布结果正确。所有真实动作必须经由受控工具，所有正式指标必须通过确定性校验。

1. 一张总流程图

用户问题

↓

↓

↓

↓

回写给模型（role=tool）+ 写入 events.jsonl
↓
模型继续下一步，或输出最终结论

2. 工具调用如何实现？

TOOL SCHEMA

工具先声明能力

每个 Tool 定义名称、描述、JSON Schema 和 execute()。模型只看到 Schema，不能看到或调用任意 Python 函数。

ALLOWLIST

工具白名单

default_tools(workspace) 组装允许工具；Agent 将它们放入 by_name 字典。模型请求未知工具会被拒绝。

GATEWAY

统一执行网关

Agent._execute() 是所有调用入口，负责查找工具、校验参数和捕获异常。

# Agent._execute() 的关键逻辑（简化）
tool = self.by_name.get(name)
if not tool:
    return "Error: unknown tool"

inspect.signature(tool.execute).bind(**arguments)  # 参数是否合法
return tool.execute(**arguments)                   # 真正执行
为什么这一层重要？模型可能返回 run_shell、delete_database 或传入错误参数，但项目没有这些工具，或参数不符合函数签名，调用就不会真正发生。

3. 工具调用结果怎样回到 Agent？

模型提出调用
例如：run_backtest(script_path, result_path)。
程序执行并取得字符串结果
成功时是 JSON；失败时同样是结构化 JSON，包含 failure_category、repair_hint 与裁剪后的 stderr。
结果写入上下文
Agent 添加 {role: "tool", tool_call_id: ..., content: result}。下一轮模型看到的是工具事实，而不是猜测。
结果写入审计
记录 round、工具名、参数、结果、耗时、失败类别和缓存命中情况；Web 的 Agent Trace 就来自这些事件。

4. 回测结果如何校验？

最严格的校验发生在 tools/backtest.py。它不信任脚本的 stdout，也不信任模型文字，只认指定位置生成的 JSON Artifact。

校验阶段当前实现拦截的情况
路径校验脚本和结果都通过 workspace-relative path 解析../ 越界、访问工作目录外文件
脚本校验必须是存在的 .py 文件路径错误、非 Python 文件、缺失脚本
执行边界不通过 Shell；subprocess.run([python, -I, script])；超时上限 300 秒Shell 注入、长时间卡死、继承过多运行环境
陈旧结果防护运行前删除已有 result 文件脚本本次没写结果，却误用上次旧 Artifact
文件与 JSON 校验退出码为 0 后仍要求 result 文件存在，且能解析为 JSON object脚本“表面成功”、没产物、JSON 损坏
指标 Schema必须有 sharpe、max_drawdown、turnover；必须是有限数值字段缺失、字符串、布尔值、NaN、Infinity
风险值范围max_drawdown、turnover 不允许为负常见符号或计算协议错误
曲线 Schema最多 10,000 个点；每点必须是 [date_string, numeric_value]格式错误、超大工件、NaN 曲线值
内容证据对写入的 JSON 计算 artifact_sha256后续无法确认指标来自哪份具体工件

5. 回测失败如何分类？

syntax_error

语法错误

stderr 包含 SyntaxError 或 IndentationError。

missing_dependency

依赖缺失

stderr 包含 ModuleNotFoundError 或 ImportError。Agent 被提示不要自动装包。

data_or_schema_error

数据或字段问题

stderr 包含 FileNotFoundError 或 KeyError，通常代表路径、列名或数据结构不符合预期。

timeout

运行超时

脚本超过允许时间，Runner 主动停止它。

missing_result

没有结果工件

脚本退出码为 0，但没有生成指定 JSON。

invalid_result

结果不合法

JSON、指标或曲线 Schema 不符合协议。

6. 缺失数据当前是怎样检测的？

当前已实现的检测分三层：
  • 上传层：只接受 CSV、JSON、Parquet、XLSX；拒绝不支持的扩展名和超过 50MB 的单文件；记录 SHA256、大小、时间和关联 Run。
  • 脚本运行层：缺文件会成为 FileNotFoundError；缺字段常成为 KeyError；二者归类为 data_or_schema_error。
  • 研究治理层：validate_research 检查研究登记是否有 data_sources、methodology、reproduce_command，且回测指标是否完整。
# ValidateResearchTool 的必需内容
研究记录必须有：data_sources, methodology, reproduce_command
指标必须有：sharpe, max_drawdown, turnover
否则：decision = "needs_review"

7. 异常数据当前是怎样检测的？

需要诚实区分：当前项目已经能很好检测结果工件异常，但尚未实现一个通用、完整的 OHLCV 数据质量引擎。
异常类型当前是否检测实现位置 / 说明
指标 NaN、Infinity、字符串或布尔值是RunBacktestTool._validate_metrics() 使用 math.isfinite
负的 max_drawdown / turnover是结果协议检查
曲线点不是日期+数字是_extract_artifacts()
过长曲线是限制最多 10,000 点
缺失 CSV 文件或预期字段部分由脚本异常分类为 data_or_schema_error
日期乱序、重复日期、交易日缺口模板脚本部分处理；通用层未完成需要专门 Data Validator
OHLC 不合理，例如 low > high未通用实现应在上传后的数据画像阶段检测
价格为负、成交量为负、极端跳变未通用实现应配置规则和异常阈值
复权、拆股、分红、幸存者偏差未通用实现需要真实数据供应商元数据与研究协议支持

8. 特定模板如何做数据检查？

例如当前纳斯达克综合指数周度趋势模板会读取本地上传的 CSV，并在脚本中显式检查：

需要发现 *_index_history_COMP.csv
需要 date 与 close 列
日期必须能解析为 YYYY-MM-DD
至少需要 82 条周度观测
按日期升序排序
只取最近 156 条观测（约三年）

这是“策略脚本内的数据契约”。它能保护该模板，但不能替代所有 CSV 都适用的通用数据质量层。

9. 生产级应该如何补齐？

上传后先建立 Data Profile
识别列名、类型、标的、频率、时间范围、缺失率、重复率、最小/最大值与 SHA256。
使用 Data Contract
不同数据类型定义明确 Schema：OHLCV、财务报表、因子矩阵、基准数据；脚本只接收符合契约的数据版本。
规则与统计双重异常检测
规则：low ≤ open/close ≤ high、价格/成交量非负；统计：异常收益率、缺失交易日、重复时间戳、频率漂移。
公司行为与数据版本
记录 adjusted/unadjusted、拆股、分红、供应商、下载时间、股票池生存状态，避免“回测看似正确、数据其实有偏差”。
阻断而非默默修复
严重错误返回 needs_data；轻微质量问题写 warning 与影响范围；不能由模型悄悄填补价格数据。

10. 面试总结

我把工具调用设计成“Schema → 白名单 → 参数绑定 → 受限执行 → 结构化结果 → 事件审计”的链路。回测结果不信任模型文本，必须由指定脚本写出 JSON，并经过路径、进程、Schema、数值、曲线和 SHA256 校验。当前已经覆盖运行工件异常、缺失文件/字段与治理资料缺失；通用 OHLCV 数据质量验证是下一步生产化重点，会作为独立 Data Profile / Data Contract 层实现。

  • tools/forecast.py：使用可解释的 AR(1) 历史收益率情景模型，输出上涨概率、统计区间，以及滚动样本外方向准确率和 Brier score；预测 Artifact 含数据 SHA-256 与限制说明。

“分析近三年走势”不等于策略回测或预测。“上涨概率”只是历史模型产生的统计情景，不是必然价格、买卖建议或自动交易依据。复权、幸存者偏差、流动性和样本外验证仍需额外研究。
