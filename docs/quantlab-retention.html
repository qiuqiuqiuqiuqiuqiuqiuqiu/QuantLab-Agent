LOCAL RETENTION POLICY

QuantLab 的归档、清理与日志轮转

新功能采用“默认只预览、必须显式执行、先验证后删除”的安全设计，避免本地研究证据被误删。

1. 新增了什么？

01 · ARCHIVE

旧 Run 归档

把已结束且足够旧的 Run 文件夹压缩成 .tar.gz，释放活跃目录空间。

02 · DRY RUN

先预览再执行

所有会删除原文件的操作默认仅列出候选项；只有加 --execute 才真正修改磁盘。

03 · LOG ROTATION

审计日志轮转

当 audit.jsonl 达到指定大小后，原子重命名为带时间戳的历史日志。

2. 如何使用？

# 先预览：默认显示 90 天前的已结束任务，不修改任何文件
quantlab cleanup --older-than 90

# 确认列表无误后，实际归档
quantlab cleanup --older-than 90 --execute

# 预览：当全局审计日志达到 20MB 时是否需要轮转
quantlab logs rotate --max-mb 20

# 实际执行日志轮转
quantlab logs rotate --max-mb 20 --execute

3. 归档是如何实现的？

扫描候选 Run
读取每个 runs/<run_id>/manifest.json，只选择终态：completed、failed、needs_review、needs_input、needs_data。
按时间过滤
使用 updated_at，仅处理早于 --older-than 天数的 Run。正在运行的任务永远不会被归档。
计算大小并预览
递归计算 Run 文件夹中的文件大小，返回 Run ID、字节数和计划写入的归档路径，但默认不修改文件。
创建临时压缩包
执行模式下先写入 .tar.gz.tmp，避免中途断电或失败留下看似完整的归档。
验证归档内容
重新打开压缩包，确认包含 run_id/manifest.json，证明核心任务元数据已成功写入。
原子替换后才删除源目录
临时文件原子改名为正式 .tar.gz；仅在验证通过后删除原始 Run 文件夹。
安全边界：归档功能只处理 .quant-agent/runs/ 中的 Run 文件夹。它不会自动删除上传的 CSV、数据资产、回测脚本或 artifacts/，因为这些内容可能被其他研究复用。

4. 归档后文件在哪里？

.quant-agent/
├── runs/                         # 活跃、近期或仍在运行的任务
│   └── run_20260827_xxx/
└── archive/
    └── runs/
        └── 2026-05/              # 按 Run 最后更新时间分月
            └── run_20260512_xxx.tar.gz

5. 日志轮转如何实现？

全局 audit.jsonl 是追加式文件。如果一直写入，它会变得很大。轮转不是删除日志，而是把旧日志改名，随后下一次审计写入会自动创建一个新的 audit.jsonl。

检查大小
读取当前 audit.jsonl 的字节数，与 --max-mb 阈值比较。
生成时间戳文件名
例如：audit.20260827T153000Z.jsonl。如果碰撞则加递增序号。
原子 rename
使用同一文件系统内的 Path.replace() 改名，不重写历史 JSONL 内容，因此不会丢掉已有事件。
后续自动创建新日志
AuditLog.record() 下次追加时会自动创建新的 audit.jsonl。

6. 为什么没有“一键删除所有旧文件”？

内容当前策略原因
已结束的 Run可安全归档Run 文件夹是相对独立的研究执行记录
audit.jsonl轮转，不删除审计证据通常需要保留
上传的 CSV / Parquet不自动删除可能被多个 Run 或后续复现引用
backtests/*.py不自动删除脚本是研究可复现性的关键证据
artifacts/*.json暂不自动删除未来需先建立“哪个 Run 引用了哪个 Artifact”的引用计数

7. 对生产环境的下一步

当前实现适合本地单机。生产环境可以增加保留策略配置、归档清单、对象存储生命周期、Artifact 引用计数、删除审批和恢复演练。

自然语言任务→ 行情快照→ 数据校验→ 策略 / 预测→ 受限计算→ 证据/治理
  • tools/market_data.py：经固定 Alpha Vantage 适配器获取 OHLCV，校验日期、必填字段、重复日期、价格高低关系和成交量；保存 CSV、lineage JSON、SHA-256。Key 不进入 LLM 上下文。
  • tools/strategy_template.py：只允许 buy_and_hold、moving_average、mean_reversion 三种策略；校验窗口、z-score、成本和 CSV 列后，生成可审阅的策略规格与标准库脚本。
  • tools/forecast.py：使用可解释的 AR(1) 历史收益率情景模型，输出上涨概率、统计区间，以及滚动样本外方向准确率和 Brier score；预测 Artifact 含数据 SHA-256 与限制说明。
  • 策略脚本保存到 backtests/generated/，规则保存到 .quant-agent/strategy-specs/，回测和预测结果保存到 artifacts/；run_backtest 仍负责无 Shell 执行、超时、JSON Schema 与 SHA-256 校验。
“分析近三年走势”不等于策略回测或预测。“上涨概率”只是历史模型产生的统计情景，不是必然价格、买卖建议或自动交易依据。复权、幸存者偏差、流动性和样本外验证仍需额外研究。
