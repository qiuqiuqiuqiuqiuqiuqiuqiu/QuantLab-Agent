QuantLab Agent
本地量化研究工作台

一个帮助团队把“我想研究某只股票、策略或统计预测情景”变成可计算、可复现、可追溯实验的 Agent 系统。

研究辅助，不自动交易，不构成投资建议

用一句话说清楚

你提出问题、选择研究模板或上传数据；QuantLab Agent 负责安排研究步骤、调用受控工具、运行计算、生成图表，并保存完整的证据链。它不是聊天式股票推荐器，而是一个本地的研究流程管理系统。

它实际能做什么？

01 · PROJECT

创建研究项目

例如创建“AI Semiconductor Research”，保存研究假设、股票池和基准。

02 · EXPERIMENT

连续做多个实验

在同一项目下做 NVDA 单股体检、NVDA/AMD/MSFT 对比和策略测试。

03 · EVIDENCE

保存可验证结果

保留数据来源、参数、工具调用、回测指标、曲线和最终状态。

Agent 是怎样工作的？

模型只负责“想下一步”

模型理解用户需求，选择已定义的工具，并根据工具返回的真实结果决定下一步。它不直接计算 Sharpe，也不直接执行系统命令。

程序工具负责“做事实”

Python 工具读取数据、运行回测、校验 JSON 指标、写入研究记录。没有成功工件，就不能把结论称为已验证结果。

为什么不让 Agent 无限自动修复？

真实开发中，最危险的是“回测失败后模型无限改代码、无限重跑”。QuantLab 给 Agent 设置预算和停止条件。

最大轮次

超过总轮次，任务自动停止并要求人工复核。

重跑预算

同一回测脚本只有有限修复与重跑机会。

失败分类

区分语法、数据、依赖、超时和结果文件问题。

项目的安全与治理边界

已经实现

  • 工作目录边界；
  • 无 Shell 的 Python 进程调用；
  • 超时和结果工件校验；
  • 工具输入输出与最终状态落盘；
  • 缺数据时停止，不编造量化指标；
  • 不接交易权限，不自动下单。

真实生产下一步

  • 将回测移入一次性容器或隔离 Worker；
  • 只读数据挂载、无网络、CPU/内存限制；
  • 真实行情数据版本管理与复权检查；
  • 实验矩阵、参数扫描和项目级结果比较。

项目定位

QuantLab Agent 是一个本地 Quant Research OS 原型。它既支持历史分析、受控策略回测，也支持明确标注为不确定性的统计预测情景；重点始终是受控、可审计、可停止、可复现的 Agent 研究执行系统，而不是股票推荐或自动交易。

最新运行时能力：真实数据、受控策略与预测情景

CODE UPDATE · 2026-08-27

最新代码增加 fetch_us_market_data、create_strategy_template 与 forecast_market_direction。用户可输入 英伟达、NVIDIA 或 NVDA；LLM 决定下一步，但固定工具负责名称解析、市场数据快照、数据校验、策略编译、回测和预测诊断。

自然语言任务→ 行情快照→ 数据校验→ 策略 / 预测→ 受限计算→ 证据/治理
  • tools/market_data.py：经固定 Alpha Vantage 适配器获取 OHLCV，校验日期、必填字段、重复日期、价格高低关系和成交量；保存 CSV、lineage JSON、SHA-256。Key 不进入 LLM 上下文。
  • tools/strategy_template.py：只允许 buy_and_hold、moving_average、mean_reversion 三种策略；校验窗口、z-score、成本和 CSV 列后，生成可审阅的策略规格与标准库脚本。
  • tools/forecast.py：使用可解释的 AR(1) 历史收益率情景模型，输出上涨概率、统计区间，以及滚动样本外方向准确率和 Brier score；预测 Artifact 含数据 SHA-256 与限制说明。
  • 策略脚本保存到 backtests/generated/，规则保存到 .quant-agent/strategy-specs/，回测和预测结果保存到 artifacts/；run_backtest 仍负责无 Shell 执行、超时、JSON Schema 与 SHA-256 校验。
“分析近三年走势”不等于策略回测或预测。“上涨概率”只是历史模型产生的统计情景，不是必然价格、买卖建议或自动交易依据。复权、幸存者偏差、流动性和样本外验证仍需额外研究。
