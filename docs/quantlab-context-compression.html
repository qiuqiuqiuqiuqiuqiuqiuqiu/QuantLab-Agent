如何让 Agent 记住关键事实，又不被长输出拖垮？

QuantLab 不会把每一次工具输出、报错和 CSV 内容无限塞给模型。它在每轮模型调用前检查上下文预算，并按“裁剪 → 压缩历史 → 最后保留近期消息”的三段式策略降载。

基于当前 quant_lab_agent/context.py 与 agent.py

1. 为什么要压缩上下文？

Agent 每调用一次工具，就会把工具结果作为下一轮模型的上下文。量化研究尤其容易产生长内容：CSV 摘要、回测净值曲线、Python traceback、数据质量报告和多轮策略修复记录。如果不控制，它会带来上下文超限、延迟上升、Token 成本膨胀，以及模型被旧错误干扰的问题。

PROBLEM 01

工具输出很长

一个失败回测的 stderr 或一份数据诊断，可能是数千到数万字符。

PROBLEM 02

历史越跑越贵

每轮都会重新发送此前消息；旧内容会在后续请求中重复计费。

PROBLEM 03

关键证据会被淹没

模型可能反复关注旧 traceback，而忘记最新数据路径、规则和失败原因。

4. 举一个真实任务例子

用户要求：“获取 NVDA 数据，生成均线策略，回测失败后修复，并给出预测情景。”

压缩前

  • 原始用户任务；
  • 市场数据工具返回的 CSV 元数据；
  • 策略规格 JSON；
  • 第一次回测完整 stderr（8,000 字符）；
  • 读取脚本的完整内容；
  • 修复 diff；
  • 第二次回测结果和预测结果。

模型每一轮都带着全部内容，越来越慢、越来越贵。

第一层裁剪后

  • 长 stderr 只保留开头的错误类型；
  • 再保留结尾的 traceback 行；
  • 中间大量重复栈帧被替换为 …[tool output trimmed]…；
  • 最近的策略参数和结果仍完整存在。

模型通常仍足够判断：是缺文件、字段错误还是语法错误。

审计不会因为压缩而丢失：工具完整结果会先写入 audit.jsonl 和对应 Run 的 events.jsonl；被裁剪的是“下一次送给 LLM 的工作记忆”，不是证据存档。

5. 开发中会遇到什么问题？如何处理？

CASE 01 · 直接截断会丢失真正的错误行

问题

如果只保留工具输出前 1,000 字符，Python traceback 最有价值的最后几行往往丢失。模型看不到异常类型、脚本行号和失败原因，只能猜。

当前解决

第一层同时保留前 1,200和后 400字符。开头通常有结果/状态，结尾通常有错误栈末端；中间重复内容不再占上下文。

CASE 02 · 只压缩工具结果，历史对话仍会无限增长

问题

即使每份工具结果都不长，多轮“模型计划 → 工具结果 → 模型修正”仍然会积累大量消息。

当前解决

超过 70% 上下文预算时，将较早历史提炼成一个压缩历史块，只保留最近 6 条原始消息。这样优先保留刚刚发生的调用与最新结果。

CASE 03 · 压缩本身也可能消耗 Token

问题

如果调用另一个 LLM 来总结历史，摘要调用本身会增加费用和失败点。

当前解决

当前 ContextManager 是纯本地、确定性的字符裁剪与提取式摘要，不会增加一次模型调用、不会泄露更多数据，也便于离线测试。

CASE 04 · 只限制上下文，仍可能花超总预算

问题

单次上下文未超模型窗口，不代表整个 Run 不会累计消耗大量 Token。

当前解决

Agent 另有 max_total_tokens 预算。每次调用前会估算“已用 Token + 下一次输入 + 最大输出预留”；不足则不发起模型请求，进入人工复核。

6. 当前实现的局限：必须诚实说明

当前不是语义级 RAG 摘要。第二层仅提取旧消息前 240 字符，可能遗漏一条消息后半部分的重要参数；模型工具调用中的结构化 tool_calls 也不会被完整浓缩为业务事实。紧急折叠只保留最后 4 条消息，可能丢失最初假设。完整审计仍在磁盘，但模型不会自动重新读取。
当前实现优点生产级下一步
字符数 ÷ 4 粗略估算 Token无依赖、速度快、足够做防守性预算按模型 provider tokenizer 精确计数，并留出 tool schema 开销
提取式旧历史摘要确定性、不额外调用 LLM将研究 ID、数据路径、策略参数、最近失败原因做结构化事实卡片
每个 Run 内存消息列表实现简单持久化 checkpoint、摘要版本和 step-level resume
工具输出统一裁剪能快速降低长 traceback 成本按工具类型制定摘要：保留指标、路径、哈希、错误码，丢弃噪声

7. 面试时可以怎样总结？

我把上下文看作一项有限预算，而不是无限聊天记录。QuantLab 在每轮模型调用前按三层策略处理：先裁剪异常长的工具输出，再把旧历史压缩为本地确定性的提取式摘要，最后在接近极限时只保留近期消息。同时，完整工具证据仍写入 JSONL 审计日志；上下文压缩影响的是模型工作记忆，不影响可追溯性。再配合最大轮次、总 Token 预算和回测重跑预算，Agent 才能在长任务中可控地停止。
