Docker 是什么？
QuantLab 如何使用 Docker？

根据项目中的 Dockerfile 与 docker-compose.yml 整理，帮助你理解“项目已经配置了 Docker”与“镜像已构建并运行”之间的区别。

1. 你的项目已经被 Docker 封装了吗？

准确答案：项目已经具备 Docker 封装配置，因为根目录中已有 Dockerfile、docker-compose.yml 与 .env.production.example。但是，只有运行 docker compose up --build -d 后，镜像才会在你的电脑上真正构建，容器才会真正运行。

可以理解为：你已经写好了“做菜说明书”和“开店配置”，但是否已经做出菜、是否已经开店，要看你有没有执行构建和启动命令。

2. Docker 到底是什么？

Docker 是一种把应用和运行它所需环境一起打包的工具。它让程序在不同电脑上尽量以同样方式运行。

没有 Docker： 同事电脑 → 安装 Python → 创建 venv → 安装依赖 → 安装 Node → npm install → 匹配版本 → 配置环境变量 → 启动前后端 有 Docker： 同事电脑 → 安装 Docker Desktop → 配置 .env.production → docker compose up --build -d
IMAGE

镜像 Image

像应用的“安装包/模板”。里面包含系统基础、Python、依赖、前端构建产物和项目代码。

CONTAINER

容器 Container

镜像真正启动后的运行实例。可以把它理解成“正在运行的 QuantLab”。

VOLUME

数据卷 Volume

独立于容器保存数据。容器删掉后，研究数据仍可保留。

3. 当前 Dockerfile 做了什么？

项目的 Dockerfile 使用了多阶段构建：先用 Node 构建 React 前端，再用 Python 运行最终服务。

阶段一：frontend-build
使用 node:22-bookworm-slim；复制 frontend/package*.json；执行 npm ci；执行 npm run build，产生静态前端文件。
阶段二：runtime
使用更轻的 python:3.12-slim；安装 .[openai,web]；复制 QuantLab Python 代码；把前端构建结果复制到 frontend/dist。
生产环境变量
设置 QUANTLAB_ENV=production、QUANT_AGENT_WORKSPACE=/data、SQLite 路径为 /data/.quant-agent/quantlab.db。
安全运行用户
创建 UID 为 10001 的 quantlab 用户，容器不使用 root 用户运行 API。
启动 FastAPI
容器启动命令是 uvicorn quant_lab_agent.web.api:app --host 0.0.0.0 --port 8000。

4. docker-compose.yml 做了什么？

services:
  quantlab:
    build: .
    ports:
      - "8000:8000"
    env_file:
      - .env.production
    volumes:
      - quantlab-data:/data
    restart: unless-stopped
    security_opt:
      - no-new-privileges:true
    read_only: true
    tmpfs:
      - /tmp
配置含义为什么需要
build: .根据当前目录 Dockerfile 构建镜像把项目代码和依赖打包
8000:8000宿主机 8000 映射到容器 8000浏览器可访问 localhost:8000
.env.production把 Key、模型名、管理员配置传入容器敏感配置不写死在镜像中
quantlab-data:/dataDocker 命名数据卷保存 SQLite、Run、日志、上传数据和 Artifact
restart: unless-stoppedDocker 重启后自动恢复服务适合长期本地或服务器运行
read_only: true容器根文件系统默认只读减少意外写入；只有 /data Volume 和 /tmp 可写
no-new-privileges禁止进程获得额外系统权限提供一层基础安全防护

5. 数据实际在哪里？

浏览器 http://localhost:8000 │ ▼ 宿主机端口 8000 │ ▼ Docker 容器中的 FastAPI :8000 │ ▼ 容器内 /data │ ▼ Docker Volume：quantlab-data ├── .quant-agent/quantlab.db ├── .quant-agent/runs/ ├── .quant-agent/uploads/ ├── .quant-agent/audit.jsonl └── artifacts/
重要：Docker 模式中，数据默认不在代码目录的 .quant-agent/，而是在 Docker 的 quantlab-data Volume 中。因此直接复制 Git 仓库不会自动带走已有 Run、用户和上传数据。

6. 如何真正启动 Docker 版本？

# 1. 进入项目目录
cd /Users/yanxiaojing/code/QuantLab_Agent

# 2. 创建生产配置
cp .env.production.example .env.production

# 3. 编辑 .env.production，填写 API Key、随机 Secret 和管理员密码
# 4. 构建并后台启动
docker compose up --build -d

# 5. 查看服务状态
docker compose ps

# 6. 查看日志
docker compose logs -f

# 7. 浏览器打开
# http://localhost:8000

7. Docker 对“发给别人运行”有什么帮助？

方便

环境一致

对方不用自己处理 Python、Node、依赖版本和前端构建步骤。

方便

启动一致

只需 Docker Desktop、自己的 .env.production 和一条 Compose 命令。

仍需注意

数据和密钥不自动共享

对方必须使用自己的 API Key、Secret、管理员密码，并获得一个新的空数据 Volume。

适合你的项目：Docker 很适合面试演示、小团队内部部署和交付给其他开发者。它让“本地 Agent + FastAPI + React + SQLite + 数据卷”变成可复制的单机部署单元。

8. 面试时的一句话

我使用多阶段 Docker 构建：Node 阶段构建 React，Python 阶段运行 FastAPI；运行数据通过独立 Docker Volume 持久化，敏感模型配置通过环境文件注入。这样项目可以在其他电脑上通过 Docker Compose 快速启动，同时把代码、密钥和研究数据分离管理。
